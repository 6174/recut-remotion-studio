# 科技新闻解读（faceless-explainer）

> 场景技能：这是「科技新闻解读」的导演手册。用户选中本场景后，AI 按本文件的分镜策略、视觉语法和动画纪律改写 composition。模板代码在 `template/ProjectVideo.tsx`，beat 渲染器在 `beats.tsx`，视觉源语在 `primitives.tsx`；三者必须保持一致。

## 一、场景定位

- **适合**：每日 AI、芯片、软件、硬件和产品发布新闻；把一条消息讲成“发生了什么、为什么重要、接下来该看什么”。
- **不适合**：需要展示真实产品界面或演示录屏的发布片（用 `product-launch`）、纯人物采访、没有明确新闻事件的泛知识课。
- **叙事承诺**：不复述新闻稿，不制造焦虑；每个镜头替观众完成一次更清楚的判断。

## 二、默认视觉：渐变荧光绿科技报纸

这是一个高风格化的科技媒体视觉模板，借鉴“网格纸 + 黑色大字 + 荧光 marker + 手绘箭头”的强传播海报语言：

- **纸面秩序**：暖白底与细黑网格是全片底色，像一张可被标记的新闻草稿；网格只做背景，绝不承载内容。
- **层次渐变**：场景大底必须同时使用暖白到冷青的底色渐变、两处径向光晕和 marker 多 stop 渐变；大色块不能是单一纯色。渐变只属于本场景，不上升为平台默认。
- **焦点色**：荧光绿（`FACELESS_EXPLAINER_PALETTE.accent`）与青绿、浅蓝组成 marker 和标题渐变；黑字永远保留清晰轮廓，渐变只增加视觉层次，不牺牲对比度。
- **情绪符号**：不规则 marker 色块、粗笔曲线箭头和夸张眼睛都来自 `primitives.tsx` 的确定性 SVG，不用随机数、外部贴图或装饰性小字。
- **大字纪律**：标题使用 88–126px；正文 ≥48px，逐词字幕 ≥40px，编号和 CTA ≥44px。字幕是无底框的下三分之一旁白层，采用白字黑描边、克制逐词放大，不能遮住正文或新闻卡。读不到的字必须删除，绝不能缩小塞进画面。
- **反标签纪律**：`kicker` 只能作为 54px 以上的构图文字，不能做成 tag、chip 或胶囊；没有叙事价值的编号和元数据直接删除。
- **内容密度**：一个 beat 只有一个新闻判断，文本过多时删减或拆镜头；不要用“新闻列表”和小字装出信息量。

## 三、导演视角：一条新闻，三问读懂

开场三秒先给新闻钩子，中段依次把标题拆为事实、影响与信号，结尾给观众一条可带走的判断。动效落定后至少留 0.5 秒阅读时间。

| # | beat | 导演意图 | 唯一视觉主角 | 动画展开 | 时长 |
|---|---|---|---|---|---|
| ① | `hook` | 抓住今天值得读的一条消息 | 荧光 marker 上的超大新闻标题 + 眼睛 | 标题上浮、箭头推出 | 5s |
| ② | `concept` | 给出阅读新闻的独特视角 | 居中大主张 + 三枚粗体判断标签 | 色块/标签错峰落定 | 6s |
| ③ | `evidence` | 拆出标题背后的事实 | 三条大字号问题 + `WHY?` 新闻卡 | 步骤逐项落下 | 6s |
| ④ | `example` | 让抽象判断落在一类真实事件 | 案件卡 + 一句具体追问 | 新闻卡从 marker 色块前弹入 | 5s |
| ⑤ | `analogy` | 纠正观众的观看角度 | “看起来像 / 其实要看”箭头对照 | 曲线箭头推进 | 5s |
| ⑥ | `data` | 给出值得持续追踪的信号 | 超大 `3` + 三个判断问题 | 数字落定，问题依次显现 | 6s |
| ⑦ | `recap` | 把方法压缩成每日清单 | 三张黑框新闻便签 | 便签错峰落下 | 6s |
| ⑧ | `conclusion` | 留下一句可转述的判断 | 荧光 marker 上的结论大字 | 结论落定、进度条推进 | 5s |

**铁律：每个 beat 只有一个眼睛应该看的对象。** 全片不重复让同一种动效成为主角；箭头可以反复作为视觉语法，但每一处都只指向一个新判断。

**全片纹理镜头（默认开启）**：`buildFacelessExplainerGpuPlan` 为每个 beat 使用 `vintage` GPU 材质，以低强度颗粒、轻微褪色和暗角统一纸面质感；hook 使用轻量 `drift` 建立纸面，data 使用缓 `push-in` 收束数字，其余 beat 固定机位以保护阅读；不再绘制会压暗正文的 spotlight/focus overlay。内容表面经 HtmlSurface 光栅化，纹理由 Three-first GPU 后处理完成。

## 四、组件与素材纪律

- 必须复用 `primitives.tsx` 的 `Grid`、`MarkerBlob`、`DoodleArrow`、`DoodleEyes`、`PaperCard`、`StepList` 与 `DataBars`。这些原语已经固化了渐变、对比度、字号和确定性；`MarkerChip` 仅为旧 workspace 保留，不得用于新镜头。
- `DigitRoll` 只用于已确认的数字，`DataBars` 只用于真实占比或趋势；没有可靠数据时，改用三个判断问题，绝不填示例百分比。
- 没有真实素材时，画面全部由程序化图形构成；不得伪造新闻截图、采访画面、产品界面、数据图表或公司事实。
- 有真实媒体 assetId 时，用 `resolveMediaUrl(assetId, media)` 放进对应 evidence/example，并调用 `composition.assets` 登记；不要把聊天预览 URL 当素材。

## 五、执行步骤

1. 调用 `workflow.context` 获取路径，调用 `workspace.ensure` 确保工程就绪。
2. 先读 `template/ProjectVideo.tsx`、`beats.tsx`、`primitives.tsx` 与本手册；确认使用荧光绿纸面 palette，而不是回退为普通蓝色讲解卡。
3. 写 `SCENE_PLAN.md`：一句新闻钩子、事实、影响、三条信号和结论；运行 `validate-scene-plan.mjs` 校验。
4. 改写 `buildFacelessExplainerScenes` 的文案和真实数据，不改坏八类 beat 的信息层级与阅读时间。
5. 保存后在 Player 逐帧检查。缩到约 480px 宽时，所有要读的文字仍必须清楚；不清楚就删、拆或放大。

## 六、验收

- 结构：新闻钩子 → 阅读视角 → 事实 → 影响 → 信号 → 结论；每段只带来一个新判断。
- 视觉：暖白到冷青的渐变网格、荧光绿多 stop marker、渐变黑字、箭头和眼睛形成统一的科技媒体个性；无默认蓝色信息卡回退。
- 可读性：主信息有效字高 ≥56px，逐词字幕 ≥40px，辅助信息 ≥32px；没有“似乎有内容、却读不清”的小字。
- 真实性：无伪造指标与图表；真实素材已登记 assetId。
- 时长：默认 55s（5/6/6/6/5/5/5/6/6/5）；按具体新闻删减到 20–55s，但不压缩阅读时间。
