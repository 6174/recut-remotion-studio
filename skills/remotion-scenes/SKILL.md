# Remotion Studio 场景路由

> 本技能复用 HyperFrames 的场景分流思想，但只定义 Recut 当前拥有真实输入和可渲染能力的路径。执行实现时必须继续遵循 `remotion-studio` 的 workspace、素材登记、确定性渲染与预览确认契约。

收到 UI Prompt 中的场景 id 后，只读对应章节；不因为名称相似而调用 HyperFrames CLI、Figma 或 GitHub。没有明确场景 id 时，回到 `remotion-studio` 的普通创作流程。

## faceless-explainer

适用：文章、选题、脚本、知识讲解；没有需要展示的真实人物、网站或录屏。

- 开场三秒给结论、反常识或问题，再用 3–6 个单一信息镜头递进，结尾回收结论。
- 视觉用排版、图解、图表、抽象形状和程序化动画建立；不要伪造实拍 B-roll 或不存在的产品界面。
- 一条信息一种视觉隐喻，动效落定后保留阅读时间；默认使用清晰的逐词或动能字幕主题。

## product-launch

适用：产品发布、功能介绍、产品更新；可选截图、录屏、Logo 或演示素材。

- 结构固定为结果承诺、痛点、功能证据、行动号召；每个功能对应一个能看懂的证据镜头。
- 有真实截图/录屏时用 `resolveMediaUrl` 展示，不手绘仿冒 UI；无素材时只讲 Brief 已确认的能力，不虚构页面和数据。
- 克制使用 PageCam、DigitRoll、FlatPanel 等组件；产品画面稳定优先于炫技运镜。

## slideshow

适用：照片、截图、活动记录或素材故事；至少有一个图片或视频 asset。

- 先按情绪和叙事价值排序，绝不按文件名或上传顺序机械轮播。
- 每张关键图片都应有独立停顿；在相邻镜头之间交替使用静止、推近、平移，避免持续同一运镜。
- 所有已用素材必须登记到 `composition.assets`，没有合适素材的段落保留干净的程序化视觉。

## talking-head-recut

适用：单主体、音频清晰的口播视频。

- 先根据真实音频转录和分段；保留说话者作为主叙事锚点，删去寒暄和重复后再安排辅助画面。
- 字幕逐词对齐、无底框，只有关键短语可以放大或强化；避免每句话都抢画面。
- 不伪造新的人脸、动作、口型或发言；素材已有烧录字幕时不叠加第二套字幕系统。

## music-visual

适用：一段音乐、歌曲或具有明确节奏的音视频。

- 先找出段落、能量变化和可验证歌词；镜头切换和文字进入只在这些节点附近产生节奏，不做随机抖动。
- 最高能量段只设一个主视觉高潮，其他段落让画面呼吸；无歌词或歌词未确认时不编造字幕。
- 保持所有动画由 frame 驱动，画面和声音引用真实 assetId。

## captioned-clip

适用：想把一个原始音视频中的单一观点制作成可传播的短片。

- 先挑一段自洽观点，剪掉前言和重复；字幕保证逐词同步、对比充分且在安全区内。
- 大部分文字保持阅读轨道，只有一句真正的结论可成为视觉高潮；不在同一时刻堆叠多组强调字幕。
- 先检查原始画面是否已有烧录字幕、复杂文字或镜头频繁切换；若有冲突，保留原画面或改选片段，不能用遮挡补救。
